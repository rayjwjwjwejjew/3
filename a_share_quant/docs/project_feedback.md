# 项目反馈与基础架构改进

> 执行日期：2026-07-29
>
> 状态：V1 可以作为研究工作台运行；**不是实盘或可盈利系统**。

## 本轮已修复

1. **真实 Baostock 字段适配**：原代码读取内部别名 `trade_status`，而供应商返回 `tradestatus`，导致真实行情下载逐只失败。现已修正，并增加回归测试。
2. **批量下载会话生命周期**：原实现每只股票登录/退出一次；现在一批股票复用单一 Baostock 会话，显著降低全市场下载的连接开销。
3. **股票池输入边界**：默认下载现在只选 `type=1`、`status=1` 的在市普通股票，排除指数等非股票条目。
4. **稳健性模块性能**：修复将日期误写成数百个 DataFrame 列的问题；真实 overfit 运行不再产生该性能警告。
5. **测试收集**：此前 5 个稳健性测试没有 `test_` 前缀，pytest 不会执行；现已纳入测试集。
6. **界面层分离**：主题与数据来源提示迁至 `src/webapp/theme.py`；`app.py` 保留页面编排与研究逻辑。真实数据模式下，成本压力测试不再退回合成数据。

## 仍然阻塞研究可信度的事项

| 优先级 | 问题 | 影响 | 通过标准 |
| --- | --- | --- | --- |
| P0 | 无冻结的全市场点时快照 | 无法排除样本漂移与成分幸存偏差 | 版本化原始数据、哈希清单与 as-of 边界 |
| P0 | 无 DSR、CSCV/PBO、锁定 OOS | 参数扫描仍可能产生研究过拟合 | 试验次数登记、DSR/CSCV 报告、不可改 OOS |
| P1 | 基准仍是等权股票近似值 | 无法判断相对真实指数的超额收益 | 接入沪深 300/中证 500 点时基准 |
| P1 | 订单成交是简化的 T+1 开盘模型 | 涨跌停、停牌与冲击成本仍可能过于乐观 | 按参与率建模冲击成本，保留不可成交记录 |
| P1 | 默认全市场下载尚无断点续传/校验清单 | 大规模获取受网络中断影响 | 分批 manifest、重试、已完成代码跳过 |
| P2 | Web App 的数据抽样未展示样本构成 | 用户可能把局部样本误读为全市场 | 显示市场、股票数、起止日、数据哈希 |

## 当前决策

- `order_authority = NONE`
- 真实券商连接保持关闭
- 回测和 Web App 仅用于研究、复核和参数探索
- 任何“最高收益组合”都只可作为下一轮假设，不能直接推广或交易

## 后续计划

1. **数据可信度**：为股票型全市场下载加入分批 manifest、哈希、断点续传和点时快照；完成后才重跑 2018 至今的全市场样本。
2. **研究可信度**：预先冻结参数与 OOS 区间，接入真实指数基准，并交付 DSR、CSCV/PBO、成本压力和锁定 OOS 报告。
3. **策略研究**：只在第 2 步通过后，加入反转与低波两个独立因子；分别比较，禁止按回测最高收益拼接参数。
4. **产品与运维**：在 Web App 显示数据快照、样本覆盖、基准、研究状态和“不可交易”提示；模拟盘至少稳定运行 30 个交易日后再评估任何券商集成。
