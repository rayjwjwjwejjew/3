# 策略规范：A 股中期动量月频策略 V1

> 本文档是策略的**单一事实来源（Single Source of Truth）**。
> 代码、回测报告、配置项都必须与本文档一致；任何修改请同时更新本文档。
> 文档版本：V1（2026-07-29 起草）

---

## 0. 版本目标

V1 唯一目标：**验证系统闭环是否正确，不追求盈利**。

完成标志：
1. 能下载并清洗 2008-01-01 至最近一个交易日的日线数据；
2. 每 20 个交易日按规则生成目标持仓；
3. 模拟在 T+1 开盘价成交，扣除成本后得到净值序列；
4. 输出回撤、换手率、年度收益等基础报告；
5. 同一任务运行两次结果一致（幂等）。

**V1 明确不做的事（写下来防止诱惑）：**
- 机器学习预测涨跌；
- 分钟级或高频交易；
- 新闻、舆情、大模型选股；
- 10 个以上因子的混合打分；
- 自动实盘下单；
- 为提高回测收益而调整参数；
- 财务因子（季报披露时点与历史修订容易引入未来数据）；
- 融券、做空、杠杆、ETF、可转债、港股通。

## 2. 数据约定

### 2.1 数据范围

| 数据 | 起止 | 来源（V1 用 baostock） | 频率 |
|---|---|---|---|
| 交易日历 | 2008-01-01 至 最新 | baostock `query_trade_dates` | 日 |
| 股票列表（含上市/退市日） | 2008-01-01 至 最新 | baostock `query_stock_industry` / `query_stock_basic` | 静态 |
| 日线 OHLCV + 成交额 | 2008-01-01 至 最新 | baostock `query_history_k_data_plus`（前复权）| 日 |
| 复权因子 | 同上 | 衍生自前复权价格 | 日 |
| 停牌状态 | 同上 | baostock `query_history_k_data_plus` 的 `tradestatus` 字段 | 日 |
| ST/*ST 标志 | 同上 | V1 阶段用 baostock 名称前缀（"ST"）识别，阶段 8 再考虑专门源 | 日 |
| 涨跌停价 | 由昨收 × 阈值（0.10/0.20/0.05）计算 | 衍生 | 日 |
| 分红送股事件 | 2008-01-01 至 最新 | baostock `query_dividend_data` | 事件 |

> **数据源决策记录**：原计划用 AkShare，但 PyPI 上现有 akshare 全部要求 Python ≥ 3.12，本项目当前 Python 3.11 环境不兼容。
> V1 阶段改用 baostock（纯 Python、无 token、Py 3.11 兼容）。待 Python 升级到 3.12 后可重新评估切换回 akshare。
> 数据字段映射以 baostock 为准，规范字段在 `src/data/schema.py` 中定义。

### 2.2 数据分层

```
data/
├── raw/        ← 原始下载数据，只追加、不手工改
└── processed/  ← 清洗后供策略使用，Parquet 格式
```

- 原始数据只读，禁止回写；
- 清洗管线为幂等：同输入必产同输出；
- 清洗前必须先通过 `validator.py` 的检查（见 §5）。

### 2.3 复权方式

**统一使用后复权（adjustment_method = "post"）**。
- 选后不复权因子乘以原始价格，避免向前复权导致历史价格被未来送股事件篡改；
- 对分红送股的处理：在事件日按"现金分红除息 + 送股按除权日开盘价再投资"的惯例调整后复权因子；
- 订单生成时再换算回"未复权价 × 复权因子"的真实价格。

## 3. 股票池

### 3.1 双层定义

明确区分两层，**这是处理停牌/涨跌停能否成交的关键**：

| 层级 | 名称 | 含义 | 输出字段 |
|---|---|---|---|
| 候选层 | `candidate_universe` | 理论上当时**应当被纳入选择范围**的股票 | 在 T 日满足 §3.2 所有条件的股票 |
| 可交易层 | `tradable_universe` | T 日**实际能成交**的股票 | candidate ∩ {未停牌} ∩ {未涨停买不到} ∩ {流动性充足} |

**只有 candidate_universe 参与排序打分；只有 tradable_universe 允许实际下单。**

### 3.2 候选池筛选条件（每日动态计算）

一只股票在 T 日属于 `candidate_universe`，当且仅当同时满足：

1. **已上市时间充足**：`T - 上市日期 >= 60 个交易日`（剔除新股）；
2. **非 ST/*ST**：`is_st(t) == False`；
3. **当日未停牌**：`is_suspended(t) == False`；
4. **流动性充足**：过去 20 个交易日的**日均成交额** ≥ 阈值（默认 ¥100,000,000，可在 yaml 调整）；
5. **数据完整**：过去 120 个交易日内，OHLCV 与复权因子无缺失；
6. **无未来信息**：T 日及之前的数据可获得，T+1 日数据不参与任何 T 日决策。

### 3.3 涨跌停价计算

- 主板：±10%；
- 创业板、科创板：±20%；
- ST/*ST：±5%；
- 上市首日不限涨幅的，按不设涨跌停处理；
- 涨跌停价 = `round(昨收 × (1 + 阈值), 2)`。

## 4. 策略信号

### 4.1 因子定义（V1 单因子）

**中期动量因子**：

$$
momentum_i(T) = \frac{adj\_close_i(T-5)}{adj\_close_i(T-120)} - 1
$$

- `adj_close` 为后复权收盘价；
- 跳过最近 5 个交易日，剥离短期反转/反转风险；
- 因子空值（上市不足 120 日、停牌超过窗口的 5%）不参与排名。

> 描述逻辑定死，参数在 yaml 中可调（见 §7）。

### 4.2 选股规则

在 T 日（**调仓日**）：

1. 计算 `candidate_universe` 中每只股票的 `momentum_i(T)`；
2. 按因子值降序排序；
3. 取排名前 `top_k`（默认 10），得到**目标持仓集合**；
4. 若 `candidate_universe` 总数不足 `top_k`，按实际可入选数量取（不补足）；
5. 重复因子值使用随机数破平（破平种子固定在 yaml 中）。

### 4.3 不在 V1 中做的事

- 不做行业中性化（V1 直接用全市场排名）；
- 不做规模中性化（V1 不分组）；
- 不做反转过滤的二次打分；
- 不做组合优化（V1 等权即可）。

## 5. 调仓与检查节奏

| 事件 | 频率 | 触发条件 | 说明 |
|---|---|---|---|
| 信号计算 | 每 10 个交易日 | 累计交易日计数 % 10 == 0 | 仅计算并保存信号，**不调仓** |
| 调仓 | 每 20 个交易日 | 累计交易日计数 % 20 == 0 | 按当前最新信号生成目标持仓并下单 |
| 数据验证 | 每次回测启动时 | 必做 | 见 §5.1 |

> 调仓与信号**完全解耦**：调仓日使用的是**最近一次完成计算的信号**，而不是当天临时算的。
> 这避免了"调仓日因数据延迟导致重算"的口径混乱。

### 5.1 数据验证（V1 必做）

每次回测或更新数据后，`validator.py` 需自动检查：

1. 同一 (股票, 日期) 无重复行；
2. 交易日历连续性（无遗漏交易日），允许长假导致的非交易日空缺；
3. 价格 > 0（非零、非负）；
4. 成交量 ≥ 0；
5. 复权因子无异常跳变（相邻两日变化 > 50% 视为异常，需人工确认）；
6. 股票不在上市日前出现数据；
7. 数据日期 ≤ 当前回测时点（**关键**：不得使用未来信息）；
8. 涨跌停价与昨收关系正确（误差 < 0.01 元）。

输出 `data_quality_report.csv`，**任何一项 fail 则中止回测**，不继续。

## 6. 仓位与订单

### 6.1 仓位规则

- **等权**：每只目标持仓权重 = 1 / `top_k`；
- 单只最大权重 ≤ 10%；
- 组合持仓数 ≤ `top_k`（默认 10），下限 = 5（不足 5 只时空仓）；
- 最低现金比例 ≥ 5%；
- 单只股票最大行业敞口 ≤ 30%（行业划分采用申万一级）。

### 6.2 订单生成

调仓日产生目标权重后，按以下步骤生成订单：

1. 计算当前组合净值；
2. 计算每只目标持仓的**目标市值** = 净值 × 目标权重；
3. 计算每只股票的**目标股数** = 目标市值 / T+1 开盘价；
4. **整手取整**：A 股买入必须为 100 股整数倍（卖出可为零碎股），向下取整；
5. 计算实际下单金额 = 整手股数 × T+1 开盘价；
6. 校验：剩余现金 ≥ 总目标金额 × 5%（保留缓冲）；
7. 校验不足时按权重等比例缩股，直到满足现金约束；
8. 生成订单：每只股票一条，包含 `BUY` / `SELL` / `HOLD` 标记。

### 6.3 订单状态机

```
CREATED → SUBMITTED → PARTIALLY_FILLED → FILLED
                                       ↘ REJECTED
                                       ↘ CANCELLED
```

- `CREATED`：订单生成但未提交；
- `SUBMITTED`：已提交模拟撮合；
- `PARTIALLY_FILLED`：部分成交（V1 模拟撮合暂不产生，统一视作 FILLED 或 REJECTED）；
- `FILLED`：全部成交；
- `REJECTED`：因涨跌停、停牌、整手取整后不足一手等原因被拒；
- `CANCELLED`：人工或风控取消。

> **CREATED ≠ FILLED**。V1 模拟撮合也要走完整状态机，便于未来扩展到实盘。

### 6.4 成交约束

订单**实际可成交**当且仅当：

| 方向 | 条件 |
|---|---|
| 买入 | T+1 日未停牌 且 T+1 开盘价 < 涨停价（不能在涨停板买入）|
| 卖出 | T+1 日未停牌 且 T+1 开盘价 > 跌停价（不能在跌停板卖出）|

不满足的订单标记为 `REJECTED`，不扣费用。

### 6.5 成本模型

| 成本项 | 默认值 | 可配置 |
|---|---|---|
| 佣金 | 0.025%（买卖各一次，最低 ¥5）| 是 |
| 印花税 | 0.1%（仅卖出收取）| 是 |
| 滑点 | 0.05%（按方向不利方向加价）| 是 |
| 过户费 | 0.001%（沪市股票买卖各收）| 是 |

## 7. 配置项（`config/strategy.yaml`）

```yaml
universe:
  start_date: 2008-01-01
  end_date: null                # null = 最新
  min_listing_days: 60
  min_avg_amount_20d: 100_000_000   # 20 日均成交额下限
  include_board: [main, gem, star]  # 主板 / 创业板 / 科创板

factor:
  name: momentum
  lookback: 120                 # 因子回看窗口
  skip: 5                       # 跳过最近 N 日
  tie_break_seed: 42

signal:
  rebalance_every: 20           # 调仓频率（交易日）
  check_every: 10               # 信号检查频率
  top_k: 10
  min_holdings: 5               # 不足则空仓

execution:
  price_basis: open_t_plus_1    # T+1 开盘价
  lot_size: 100
  min_cash_buffer_pct: 5        # 最低现金比例
  slippage_bps: 5               # 单边滑点 5 bps

cost:
  commission_rate: 0.00025
  commission_min: 5.0
  stamp_tax_rate: 0.001
  transfer_fee_rate: 0.00001

risk:
  TRADING_ENABLED: true         # 总开关；任何严重异常自动置 false
  max_single_weight: 0.10
  max_industry_weight: 0.30
  max_holdings: 15
  min_cash_pct: 0.05

logging:
  log_dir: logs/
  result_dir: results/
```

## 8. 回测引擎执行顺序（每日）

严格按此顺序执行，**任何步骤出错立即停止本轮回测**：

```
读取 ≤ T 日可获得的数据
  ↓
更新 candidate_universe
  ↓
更新 tradable_universe
  ↓
若到达调仓日：取最近一次 signal → 生成目标权重
否则：目标权重 = 上一次目标权重
  ↓
按当前持仓与目标权重生成订单（整手取整）
  ↓
按 §6.4 校验订单可成交性，否则 REJECTED
  ↓
模拟成交于 T+1 开盘价
  ↓
扣除成本（佣金 / 印花税 / 过户费 / 滑点）
  ↓
处理分红送股事件（按除权日调整现金和持仓）
  ↓
更新现金、持仓、净值
  ↓
保存每日日志
  ↓
回测结束 → 输出 §9 报告
```

**最重要的原则**：T 日收盘数据产生的信号，**不能假设自己已按 T 日收盘价成交**。V1 默认 T+1 开盘价。

## 9. 回测报告必含项

- 总收益率、年化收益率
- 最大回撤（绝对值、起止日、修复天数）
- 年化波动率
- 夏普比率（无风险利率默认 2%）
- 换手率（年化）
- 总交易次数、买入次数、卖出次数、被拒次数
- 成本占收益比例
- 相对基准（沪深 300、中证 500、中证全指）超额收益
- 每年收益柱状图与月度收益热力图
- 最长亏损周期（连续亏损月份数）
- 持仓数量随时间变化曲线
- 调仓时间点 vs 检查时间点时间线
- 订单状态分布（FILLED / REJECTED / CANCELLED）
